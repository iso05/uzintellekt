UzIntellekt Admin — Доработки

Developer-ready specification · редизайн/правки админ-панели (admin/) по итогам поэкранного аудита

Overview

Живой аудит всех экранов админ-панели выявил конкретные находки, сгруппированные в сквозные темы. Эта спека описывает доработки без изменения архитектуры: тот же стек (Vite/React 18, FSD, Tailwind + токены, общий packages/ui через @shared), тот же реальный API (grid-паттерн). Правки строго в токенах и shared/ui, по контракту ui-contract-unified. Всё выбранное пользователем — в v1.

Решение по итогам аудита: экран «Журнал» (client-side activity-log) удалён целиком как ненужный — вместе с nav-пунктом, роутом, страницей, i18n-ключами и «мёртвыми» вызовами logActivity. Поэтому тема аудит-лога из плана исключена.

Requirements

Functional

  1. Локализация меток. Латинские словарные/типовые/ролевые/статусные метки (типы работ, роль правообладателя, бейдж EXPIRED) отображаются кириллицей через общий transliterateUzLatinToCyrillic, как в dashboard. Затрагивает Дашборд (D2), Модерацию-список (M2), карточку произведения (W1, W2-роль, W3-бейдж).
  2. Паритет грида. Единый переиспользуемый тулбар грида — дебаунс-поиск, сортировка по колонкам, пагинация, фильтры — применён к Файлам (F1, F2), Договорам (C2, поиск/Экспорт), Пользователям (U1 поиск по фамилии/ПИНФЛ, U3 сортировка), Модерации-списку (M3 поиск по названию, M4 сортировка). Полный мультиполе-поиск пользователей и фильтр по дате в модерации отложены (нет серверной поддержки — см. Open Questions).
  3. Баги отображения данных. Договоры: колонка «Эгаси» показывает имя владельца, а не константу-роль (C1). Дашборд: убрать «осиротевший» суффикс при avgHours=null (D4) и лишний breadcrumb на главной (D1).
  4. Связанные сущности в карточке пользователя. Карточка пользователя показывает все его произведения и договоры списком; каждая строка кликабельна и ведёт на карточку произведения / скачивание договора (UD2 + прямой запрос пользователя).
  5. Маскирование PII. ПИНФЛ (ЖШШИР) и паспорт по умолчанию замаскированы, раскрытие по клику (UD1, W2).
  6. Воркфлоу модерации. Bulk «Маъқуллаш/Рад этиш» из списка (M1); из карточки произведения можно скачать просроченное (EXPIRED) вложение для проверки (W3).
  7. Журнал удалён (A1/A2 сняты) — экран и вся его обвязка убраны из админки.

Non-functional

  • Никаких новых палитр/компонентов — только токены и @shared/ui; drift-guard (scripts/check-no-local-shared.sh) остаётся зелёным.
  • Общие правки (тулбар грида, маска PII, транслитерация) живут в packages/ui, чтобы dashboard мог их переиспользовать.
  • Grid-запросы остаются на серверной пагинации/фильтрации (cachedGridGet), поиск дебаунсится (≥300 мс), кэш инвалидируется при мутациях.
  • i18n: все новые строки — в 4 языках (uz-Cyrl default / uz / ru / en); отсутствие ключа не должно ронять экран.

Architecture

Изменений в топологии нет. Админка — SPA, потребляет общий слой packages/ui (@shared) и реальный API через grid-паттерн. Доработки добавляют один общий примитив (DataGrid toolbar) в @shared/ui, подключают уже существующий transliterate в admin и точечно правят страницы/энтити.

Technology stack

  • React 18 + Vite 5, Feature-Sliced Design; Tailwind 3.4 + CSS-переменные-токены.
  • Общий слой: @uzintellekt/ui (npm workspaces), импорт через @shared/*.
  • Grid: cachedGridGet(endpoint, {page, size, filters:[{field,operator,value}], sort:{selector,desc}}); операторы eq, sw; серверная пагинация.
  • i18n: createI18n(resources), 4 языка; локализация словарных терминов через transliterateUzLatinToCyrillic.

Data Model

Правки не меняют сущности, но опираются на связи пользователь → произведения / договоры / файлы для карточки пользователя (UD2) и для показа имени владельца в договорах (C1).

Storage

Хранилище не меняется — всё на backend. Клиент только фильтрует grid-запросы по владельцу и кэширует ответы (cachedGridGet). Экран «Журнал» действий удалён целиком (вместе с client-side ring buffer и вызовами logActivity); серверный аудит — Advanced (см. Open Questions).

User & Request Flow

Центральный поток доработок — единый тулбар грида: поиск/сортировка/страница транслируются в серверный grid-запрос через кэш.

Authentication & Authorization

  • Без изменений: POST /auth/login, getMe role-check (ADMIN-only, NotAdminError), token-storage + silent refresh.
  • Маскирование PII (UD1/W2) — только представление; данные всё равно приходят с backend, маска клиентская (раскрытие по клику логируется в журнал действий).
  • Bulk-decide и скачивание EXPIRED-вложения используют те же admin-эндпоинты; прав доступа не расширяем.

Error Handling

  • Частичный bulk (M1): при последовательных decide собирать per-item результат; показать сводку «N успешно, M ошибок», не откатывая успешные; инвалидировать кэш один раз в конце.
  • Owner-scoped grid пуст (UD2): корректный EmptyState («нет произведений / договоров»), а не «осиротевшие» кнопки без данных.
  • Отсутствует ключ i18n / поле словаря: транслитерация — идемпотентный fallback (латиница как есть), экран не падает.
  • Скачивание EXPIRED (W3): если presigned url недоступен — тост с причиной, кнопка не «молча» задизейблена.
  • C1 без имени владельца: если grid-ответ не содержит имени — деградация до «— (открыть)» вместо ложной константы-роли; открытый вопрос по backend-полю.

Testing Plan

Unit tests (Vitest, в packages/ui и admin)

  • transliterate-обёртка для типов/ролей/статусов: латиница→кириллица, идемпотентность на уже-кириллице, пустое/undefined.
  • DataGridToolbar: дебаунс формирует корректные filters; клик заголовка тогглит sort.desc; сброс страницы на новый фильтр.
  • MaskedField: маскирует по умолчанию, раскрывает по клику, не мутирует исходное значение.
  • Owner-scoped запросы: builder фильтра для работ/договоров по userId.
  • Bulk-decide reducer: агрегирует успех/ошибку, единичная инвалидция кэша.

Integration tests

  • Карточка пользователя рендерит списки работ+договоров из замоканного grid; строки — ссылки на нужные роуты.
  • Договоры: колонка владельца показывает имя (мок с owner), fallback без имени.
  • Экспорт договоров формирует CSV с BOM/`;` и защитой от формул (как Users/Files).

End-to-end / live smoke

  • Пройти каждый экран после правок: 0 ошибок в консоли, кириллические метки, работающий поиск/сортировка/пагинация.
  • UI-проверка на 3 вьюпортах (desktop/tablet/mobile) — без переполнения/обрезки.
  • Bulk-модерация и раскрытие PII проверяются в UI без реальных мутаций клиентских данных (диалоги открыть/отменить).

Open Questions

  • Grid-возможности (прозондировано на реальном API, Phase 3). Оператор lk (contains, регистронезависимо) работает на lastName/firstName/pinfl (users) и name (works); phone/phones/fullName → 500. Фильтры ANDятся — OR между полями невозможен. Поэтому: поиск пользователей по телефону, поиск модерации по автору (вложенный rightHolders) и фильтр по дате создания (нет range-операторов) отложены до расширения backend (например, виртуальное поле search/q или операторы gt/lt).
  • Поле владельца работ (решено, Phase 4). Прозондировано: работы линкуются к пользователю через createdBy (совпадает с rightHolders[].userId); фильтр по вложенному правообладателю → 500. Карточка пользователя использует createdBy eq userId.
  • Имя владельца в grid договоров (решено, Phase 4). /contracts/grid НЕ возвращает имя — только userId. C1 решён client-side резолвом (useUserNames → getUserById, кэш). Если backend добавит имя/псевдоним в grid-ответ — резолв можно убрать.
  • Эндпоинт скачивания work-file. Подтвердить путь и то, что presigned url выдаётся для EXPIRED-файлов (W3).
  • Политика маскирования PII. Маскировать полностью или частично (последние 4)? Логировать раскрытие? По умолчанию — полная маска + лог раскрытия.
