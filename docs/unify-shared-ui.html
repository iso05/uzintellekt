Унификация общего UI-слоя: dashboard + admin

Developer-ready specification · извлечь общий слой в packages/ui/, оба Vite/React-приложения потребляют один источник через alias @shared

Обзор

Два приложения UzIntellekt — dashboard/ (пользовательский кабинет) и admin/ (админ-панель) — сегодня держат две копии общего слоя (shared/ui, дизайн-токены, tailwind.config, i18n-движок, часть shared/api/shared/lib). Цель — вынести этот слой в единый каталог packages/ui/, чтобы правка компонента/токена делалась в одном месте и автоматически применялась к обоим приложениям.

Ключевой факт: общий слой уже байт-в-байт синхронизирован — все 24 компонента shared/ui, токены (assets/styles/index.css), tailwind.config.js и i18n/index.js идентичны. admin/src/shared — строгое надмножество dashboard/src/shared. Конфликтов слияния нет: канон = admin-версия, dashboard ничего не теряет (получает formatBytes/formatNumber).

Требования

Функциональные

  1. Единый физический источник общего слоя: packages/ui/ в корне репозитория.
  2. Оба приложения импортируют общее через новый alias @shared/* (Vite + jsconfig); app-local код остаётся под @/*.
  3. Канонический общий слой = admin-суперсет: ui, api (impl: http, grid, cache, token-storage, sso, geo, auth), lib (incl. activity-log, csv, format c formatBytes/formatNumber), data/geo, config/env.
  4. Общий tailwind-preset и общие токены (@shared/styles/index.css) — один источник дизайна.
  5. i18n: общая фабрика createI18n(resources) в @shared/i18n; переводы (JSON) остаются per-app.
  6. Per-app остаётся: config/routes.js (разная навигация) → переезжает в @/config/routes.js; app-local pages/widgets/features/entities/app.
  7. После миграции оба приложения собираются, проходят тесты и работают без визуальных/поведенческих регрессий.
  8. CI drift-guard: проверка, что ни в одном приложении не появился локальный src/shared (защита от повторного расхождения).

Нефункциональные

  • Единый root node_modules (npm workspaces): зависимости общего слоя объявлены в packages/ui/package.json (react/react-dom/react-i18next — peer) и хойстятся в корень одним npm install; один экземпляр React на монорепо.
  • Две независимые сборки: каждый app по-прежнему собирается своим vite build в свой dist/; общий код инлайнится в оба бандла (tree-shaking убирает неиспользуемое, напр. login в dashboard).
  • Обратная совместимость дизайна: токены/компоненты не меняются — оба UI рендерятся идентично до/после.
  • Строго по UI-контракту проекта: только токены + shared/ui, без выдуманных палитр.

Архитектура

Монорепо на npm workspaces: каталог packages/ui/ — workspace-пакет (@uzintellekt/ui) с каноническим общим слоем; оба приложения ссылаются на него через Vite-alias @shared (резолв путей) и общий tailwind-preset, а зависимости хойстятся в единый root node_modules (резолв деп + один React). Публикации в реестр нет — пакет private.

Технологический стек

  • Каталог packages/ui/ — npm workspace-пакет @uzintellekt/ui со своим package.json (private).
  • Vite 5 alias (resolve.alias) + server.fs.allow для импорта вне корня приложения.
  • Tailwind 3.4 presets — общий packages/ui/tailwind.preset.js; content-глоб включает ../packages/ui/**.
  • i18next фабрика createI18n(resources) — общая инициализация, per-app ресурсы.
  • jsconfig paths для DX/IDE-резолва @shared/*.

Резолв модулей и сборка

Каждое приложение собирается независимо; Vite резолвит @shared в packages/ui на этапе бандлинга, а bare-импорты (radix и т.п.) — из единого root node_modules (хойст npm workspaces). Итог — два самостоятельных статических бандла.

Ключевые конфиги

// <app>/vite.config.js
resolve: { alias: {
  '@': path.resolve(__dirname, './src'),
  '@shared': path.resolve(__dirname, '../packages/ui'),
} },
server: { fs: { allow: ['..'] } },   // разрешить импорт из packages/ui вне корня app

// <app>/jsconfig.json → compilerOptions.paths
"@/*": ["./src/*"],
"@shared/*": ["../packages/ui/*"]

// <app>/tailwind.config.js
import uiPreset from '../packages/ui/tailwind.preset.js'
export default {
  presets: [uiPreset],
  content: ['./index.html', './src/**/*.{js,jsx}', '../packages/ui/**/*.{js,jsx}'],
}

// <app>/src/i18n/index.js  (per-app: свои JSON + общая фабрика)
import { createI18n } from '@shared/i18n'
import ru from './ru.json'; /* … uz, uz-Cyrl, en */
export default createI18n({ ru, uz, 'uz-Cyrl': uzCyrl, en })

Миграция — объём

  • @/shared/… → @shared/…: admin — 72 файла, dashboard — 85 файлов (механическая замена, кроме routes).
  • @/shared/config/routes → @/config/routes: admin — 12 импортёров (Sidebar, AdminLayout, ProtectedRoute, все pages), dashboard — 13 (Sidebar, DashboardLayout, Header, works-виджеты).
  • Удалить <app>/src/shared после перевода (обе копии), оставив только per-app config/routes.js (перенесён в src/config/).
  • Порядок замен важен: сначала routes-импортёры → @/config/routes, затем bulk @/shared/ → @shared/ (иначе routes уедет в packages/ui).

Тестирование

Unit / компонентные

  • Тесты packages/ui (перенесённые cache/token-storage/csv/activity-log/format/error-boundary) — запускаются из обоих приложений через @shared alias в vitest.config.
  • Оба приложения: полный npm test зелёный после перевода (admin — 110 тестов, dashboard — свой набор).

Интеграционные / сборка

  • npm run build в обоих приложениях успешен; npm run lint — 0 (eslint-boundaries понимает @shared).
  • Проверка, что tailwind не выкинул классы общего слоя (визуальный diff-скриншот до/после).

E2E / smoke

  • Живой smoke обоих приложений (dashboard + admin) — ключевые экраны рендерятся идентично, 0 ошибок в консоли, дизайн не поехал.
  • CI drift-guard: скрипт падает, если появился <app>/src/shared.

Риски и обработка

  • Tailwind purge: если content-глоб не включит ../packages/ui/**, классы общего слоя выпадут → сломается стиль. Митигация: обязательный глоб + скриншот-diff.
  • server.fs.allow: без него Vite dev запретит импорт вне корня app. Митигация: fs.allow:['..'] в обоих.
  • eslint-boundaries: FSD-правила настроены на src/**; @shared вне src — убедиться, что boundaries не ругается (общий слой = внешняя граница, как node_modules).
  • Дубли зависимостей: решено — npm workspaces хойстят зависимости в единый root node_modules (один React), рассинхрон версий исключён.
  • Повторное расхождение: кто-то снова создаст src/shared. Митигация: CI drift-guard.
